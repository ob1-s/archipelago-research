# Retry and failure semantics

One future scientific/logical attempt is keyed by a unique actor-signed `attempt_id`, exact canonical request hash, actor/lifecycle identity, and signed-authorization hash. Transport records are nested beneath it as `attempt_id:wire:N`; they never become new actors, sessions, assignments, carriers, or scientific units.

The gateway sets SDK retries to zero, freezes its own automatic retry budget at zero, and keeps a synchronous-FULL SQLite ledger. A logical-attempt primary key prevents changed-body, changed-actor, changed-lifecycle, or changed-authorization reuse. An accepted response may be durably replayed to the same still-authorized actor without another provider call only after the full response contract and signed gateway receipt are revalidated. An in-flight, rejected, invalid, or terminal ambiguous record is never automatically replayed. Accepted response text is durably `ORCHESTRATOR_ONLY`: the actor filesystem cannot access the ledger, the plaintext is transiently delivered only to the same current actor for acceptance, and it may not become successor input except through a separately declared carrier.

No backend exception authorizes a second dispatch in v1. Even `SafeToRetryError` is recorded as terminal because an arbitrary backend callable cannot mechanically prove it failed before dispatch. A real provider 429 is likewise terminal because the correlation ID is not an idempotency guarantee. Timeout, connection loss, cancellation, and unknown backend crash are `UNKNOWN_DELIVERY`: no retry, no actor acceptance, and no carrier finalization. Malformed/noncompleted/wrong-model/wrong-hash/stored/tool/program/refusal-bearing responses are terminal invalid responses.

Every transport record binds actor/lifecycle, logical and wire attempt IDs, transport ordinal, request hash, outcome, dispatch phase (`not_sent`, `sent`, `response_received`, or `unknown`), provider request ID when available, provider response ID when available, and retryability. The ledger also pins the gateway receipt ID/public key. A restarted gateway can replay a valid accepted record using that public pin; issuing a new receipt requires the matching externally provisioned private key.

Assignments are frozen before outcomes. Retry records and model outputs cannot alter later assignments, common priors, actor identity, or carrier exposure. The controller may stop/mark/censor a failed unit; it may not synthesize a replacement output, interpret partial output, resume provider context, or mint a new unit to hide the failure.
